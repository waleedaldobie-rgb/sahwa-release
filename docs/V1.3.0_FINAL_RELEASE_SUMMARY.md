## 3. نطاق التغييرات المنفذة

يتضمن الإصدار تحسينات fidelity للنسخ الاحتياطي والاستعادة، بحيث تحفظ Customer Credit metadata الخاصة بالتدقيق. كما يتضمن فصل acceptance عن artifact upload مع ثلاث محاولات رفع وفاصل 30 ثانية بين المحاولات، وrelease gate يشترط installer وSHA-256 وacceptance evidence وscreenshots وCSV وExcel.

أضيف أيضًا Financial Diagnostics بصيغة read-only، وأضيف Customer Credit liability وcash/non-cash refunds إلى reporting projection في قسم مستقل لا يغير `net_profit` أو `recognized_revenue` أو `cash_received` أو `applied_collected`. كما أضيف synthetic performance harness واختبارات UI آلية للتقارير وCustomer Credit.

تظل البنود التالية مؤجلة إلى `v1.4.0`: Inventory drill-down، وNotifications operations، وCode Signing.

## 9. حالة Reporting Change Note

تم تحديث `docs/REPORTING_CHANGE_NOTE.md` ليشرح قسم Customer Credit الجديد، cash versus non-cash refunds، صيغة `closing_customer_credit_liability`، والمثال الرقمي الرابع. تم أيضًا استبدال نسخة الملف داخل Release v1.3.0، وأصبح حجم المرفق المحدث 12,843 bytes.

يتطابق شرح الوثيقة مع مؤشرات `reportMetrics.ts` وReportsView وAccountingView وورقة Excel. توجد ملاحظتان تقنيتان غير مانعتين: الكود يصنف أي refund لا تكون طريقته `cash` كـnon-cash، بما في ذلك legacy rows التي لا تحتوي method، كما أن projection يعرض الرصيد السالب عند وجوده باعتباره integrity violation بدل تطبيق clamp داخل projection.

## 10. المخاطر والتحذيرات المعروفة

Code Signing غير موجود في هذا الإصدار وفق قرار النطاق، ولذلك يجب أخذ ذلك في الاعتبار قبل التوزيع العام واسع النطاق. كما ظهرت تحذيرات GitHub Actions المتعلقة بتقادم Node.js 20 في بعض actions، وظهر `Cache save failed` في خطوة cache save، لكن ذلك لم يمنع نجاح build أو acceptance أو release gate أو رفع artifact.

لا توجد مشكلة artifact upload مفتوحة في التشغيل النهائي؛ الرفع نجح من المحاولة الأولى. ومع ذلك، يظل من الأفضل تحديث actions المتأثرة بتقادم Node.js في دورة لاحقة، ومراجعة آلية cache independently لأنها ليست جزءًا من صحة artifact نفسه.
